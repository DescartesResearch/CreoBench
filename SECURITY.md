# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in CreoBench, **please do
not open a public issue.** Instead, use
[GitHub's private vulnerability reporting](https://github.com/DescartesResearch/CreoBench/security/advisories/new)
to report it privately.

This ensures the issue can be triaged and fixed before public disclosure.

### What to include

- A description of the vulnerability and its potential impact.
- Steps to reproduce, if possible.
- The version(s) of CreoBench affected.
- Any suggested fix, if you have one.

### What to expect

- An acknowledgement within **72 hours** of your report.
- We will work with you to understand and address the issue.
- We will credit reporters in the release notes unless anonymity is requested.

## Supported Versions

Security fixes are applied to the `main` branch. Older releases are not
actively patched.

## Scope

This policy applies to vulnerabilities in the CreoBench source code
itself. Issues in third-party dependencies should be reported upstream.
